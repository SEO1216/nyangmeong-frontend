# 커뮤니티 댓글 「@닉네임」 답글 대상 백엔드 요청서

백엔드 저장소에서 `/start`로 기획할 때 붙여 넣는다. 클래스 이름은 백엔드 코드를 읽어 확인한 것이다(2026-11-18 기준). 그 뒤에 바뀐 곳이 있을 수 있으니 이 문서의 "구현해야 한다"는 문장은 그 저장소의 최신 코드로 한 번 맞춰 본다. (작성 2026-11-18, KSJ)

## 한눈에 보기

| 순서 | 항목 | 서버 작업 | 절 |
| --- | --- | --- | --- |
| 1 | 답글 등록 때 「누구에게 단 답글인지」 저장 | 구현(컬럼 추가 포함) | 1번 |
| 2 | 댓글 목록 응답에 답글 대상 닉네임 추가 | 구현 | 2번 |
| 3 | 답글 대상 알림 | 하지 않기로 결정 | 3번 |

**서버 작업이 필요 없는 것**(프론트만 바뀐다)
- 「답글이 없는 삭제 댓글 줄 숨김」과 「마지막 답글이 지워지면 부모 줄도 숨김」: 목록 응답(`CommentMapper.selectList`)이 삭제된 댓글도 `delYn`과 함께 주므로 화면에서 계산한다.
- 삭제 토스트.

## 0. 확정된 정책

| 항목 | 값 |
| --- | --- |
| 구조 | 지금처럼 1단(원 댓글 → 답글). 답글에 단 답글도 원 댓글 스레드에 이어 붙는다 |
| 화면 표시 | 답글 본문 앞에 「@닉네임」. 사람이 고른 대상(`[답글쓰기]`를 누른 댓글)의 작성자 |
| 알림 | 「@」 대상에게 따로 보내지 않는다(2026-11-18 결정, 3번) |
| 원 댓글에 바로 단 답글 | 「@」를 보이지 않는다(대상이 스레드 맨 위 댓글이라 맥락이 같음) |
| 대상 댓글이 삭제됨 | 답글 본문은 그대로 두고 「@닉네임」만 숨긴다(2026-11-18 결정) |

## 1. 답글 등록 때 대상 저장

- 현재: `CommentService.create`가 `CommentCreateRequest.prntCmntSn`으로 부모를 찾고, 그 부모가 답글이면 원 댓글로 올려 `prntCmntSn`을 정한다(`CommentService` 71~72행). 이 과정에서 사람이 누른 댓글이 사라진다. 그래서 답글 B가 원 댓글 A에 단 것인지, 같은 스레드의 답글 A2에 단 것인지 알 수 없다.
- 요청: 올려 쓰기 전의 `req.prntCmntSn()`(사람이 고른 댓글)을 새 컬럼(`CMNT.RPLY_TRGT_CMNT_SN`, 이름은 서버 규칙에 맞게)에 저장한다. 스레드를 묶는 `PRNT_CMNT_SN`과 정렬은 그대로 둔다.
- 검증: 대상 댓글은 같은 글(`pstSn`)의 삭제되지 않은 댓글이어야 한다(지금 `selectComment`가 `DEL_YN='N'`만 읽어 같은 검사가 이미 된다). 최상위 댓글에 바로 단 답글은 대상 값이 부모와 같아도 되고 비워도 된다. 프론트는 둘 다 「@ 숨김」으로 처리한다.
- 기존 답글은 대상이 없다(null). 프론트는 null이면 「@」를 보이지 않는다. 데이터 이행은 필요 없다.

## 2. 댓글 목록 응답에 대상 닉네임

- 대상: `CommentSummary`(목록 한 줄, `CommentMapper.selectList`의 `commentSummaryResultMap`).
- 추가 필드: 답글 대상 댓글의 작성자 닉네임(이름은 서버 규칙, 예: `rplyTrgtMbrNcnm`). 프론트는 이 키를 그대로 쓰고 다른 이름으로 바꾸지 않는다.
- 값 규칙:
  - 대상 댓글이 삭제됐으면 null. 지금 삭제 댓글은 내용·작성자·닉네임을 null로 주는 규칙(`DEL_YN='Y'`)이라 같은 규칙을 따른다. 프론트는 null이면 「@」를 숨긴다.
  - 대상 작성자가 탈퇴한 회원이면 지금 닉네임 규칙(`MemberDisplay.ncnm`)이 주는 값을 그대로 준다. 프론트는 받은 글자를 그대로 보인다.
  - 대상이 없는 답글·최상위 댓글은 null.
- 대상 댓글의 작성자 번호(`mbrSn`)는 필요 없다. 닉네임만 있으면 된다.
- 최상위 댓글의 정렬·페이징은 건드리지 않는다.

## 3. 답글 대상 알림: 하지 않는다 (2026-11-18 결정)

- 「@」로 지정된 사람에게 따로 알림을 보내지 않는다. 서버 작업 없음.
- 기존 알림 정책을 그대로 유지한다(2026-11-18 결정). 기존 정책은 「다른 회원이 내 글에 댓글을 달면 글 작성자에게 댓글 알림」이다(공통레이아웃 기능명세서 FN-COM-008-08, TC-COM-004-13). 내 댓글에 답글이 달렸을 때 댓글 작성자에게 따로 보내는 알림은 만들지 않는다.
- 댓글 알림 구현은 이 요청과 별개다(YAY `notification` 담당, 아직 구현 전). 답글 대상(1번의 새 컬럼)은 화면 표시용이라 알림 대상을 정하는 데 쓰지 않는다.

## 프론트 후속 작업 (서버가 끝나면)

- `CommentSection.jsx`: 답글 줄 본문 앞에 「@닉네임」(브랜드 색 글자)을 보이고, `[답글쓰기]`가 답글에서 눌렸으면 그 댓글을 대상으로 등록한다(요청 본문에 대상 댓글 번호). 대상 닉네임이 null이면 「@」를 그리지 않는다.
- 답글 입력 칸 위의 「○○님에게 답글」 안내는 화면 안에서 이미 대상 댓글을 알고 있으므로 서버 없이도 보일 수 있다(2단계로 나눌 수 있다).
